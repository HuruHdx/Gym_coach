# Gym Coach · 能力地图（abilities）

> **用途**：本项目所有"能力"的统一索引。每加一个新能力，在这里记一行，防止"做着做着忘了当初怎么设计的"。
> 一个能力 = 用户在聊天框或页面触发的一项能力（可能对应意图分支 / 工具调用 / 页面功能）。
> 状态：`✅ 已上线` / `🧪 已落地待验证` / `📋 方向已定未编码` / `💡 规划中`

## 一、已上线 / 已落地

| 能力 | 触发 | 输入 | 调用什么 | 状态 |
|---|---|---|---|---|
| 出计划（plan） | 用户说"帮我出/练X" | 画像 + 目标动作/部位 | 意图分支→出计划草稿 | ✅ 已上线 |
| 问答（qa） | 用户问动作/知识/建议 | 问题 | qa 分支→knowledge / 建议 | ✅ 已上线 |
| 闲聊（chitchat） | 非计划/非问答的闲聊 | 任意 | chitchat 分支→纯 LLM（短路，不触发 search） | ✅ 已上线 |
| 查训练历史（stats） | 用户问"上次/最近练了啥" | 部位/动作 | qa+统计注入（stats_fixture） | ✅ 已上线 |
| 动作库检索（knowledge） | 用户问某个动作练哪/怎么做 | 动作名 | knowledge 检索动作库 | ✅ 已上线 |
| 安全停训 | 用户带伤问训练 | 伤痛描述 | 安全分支→建议停训/就医 | ✅ 已上线 |
| 今日打卡 | 今日页执行计划 | 每组重量×次数×感受 | 打卡写入 sets + 1RM 反推 | ✅ 已上线 |
| 训练历史页 | 训练 tab | 会话数据 | dashboard / exercises 接口 | ✅ 已上线 |
| 1RM 估算（双基准） | 打卡后自动 | 完成组的重量×次数 | Epley 反推，estimate/best 双基准 | 🧪 已落地待验证 |

## 三、能力评估总览

> 这是给"流程/工具调用评测"用的：每个已上线能力 = 一条要测的路径。

**评测路径清单（已上线）**：

| 路径 | 期望行为 | 评测状态 |
|---|---|---|
| plan→出计划 | 返回草稿 | ✅ 意图已过 |
| qa→查历史 | 命中真实训练数据 | ⚠️ 流程评测过，需重启后端复核 |
| qa→动作知识 | 答对动作/部位 | ⚠️ 流程评测过 |
| chitchat | 不触发 search，纯闲聊 | ✅ 已修复短路 |
| 安全→停训 | 建议停训/就医 | ✅ 已改 |
| 打卡→1RM | 打卡后自动反推，双基准更新 | 🧪 待用户重启验证 |

## 四、使用约定

- **加能力**：在"二、规划中"加一行 → 实现了移到"一、已上线"
- **改能力**：更新对应行的"调用什么/状态"，不要另开文档
- **做评测**：从"三、评测路径清单"取待测项
- **别混**：本表是"有哪些能力+状态"；具体怎么实现看根目录对应方案 MD（设计系统/评测架构/改造方案等）
