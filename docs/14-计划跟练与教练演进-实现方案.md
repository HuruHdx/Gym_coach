# 14 · 计划跟练与教练演进 · 实现方案

> 日期：2026-11-25  
> 性质：专题方案（供评审）；**现状台账仍以 [`项目地图.md`](./项目地图.md) 为准**。  
> 范围：Gym_coach（H5 + API）+ Admin 工坊拼装；不含营养 / FormCheck / 海报大功能。

---

## 0. 一句话定位

- **计划模板** = 现成多日课表，点了就能跟。  
- **教练** = 按当天情况现排动作（也可荐模板）；出的是卡片，**点了才生效**。  
- 两条路都落到「今日场次 / 跟练指针」，**不互相审讯、不硬门禁**。  
- 核心仍是「按个人情况出**当天**该练什么」；分化模板是实用叠加。

## 1. 背景与已落地（本日已实现）

### 1.1 问题

内容工坊拆视频后，推日 / 拉日 / 肩腿等本应同属「三分化」一套计划，旧交互要手填 `append_to_plan_id`，难用。  
H5 跟练曾按**自然周**算板块进度，与「一轮 = 练完本套所有板块」心智不符。

### 1.2 已实现（代码已合入工作区，评审时请对照 diff）

| 项 | 做法 | 关键路径 |
|---|---|---|
| 工坊并入计划 | 「新建一套 / 并入已有」+ 可搜索计划列表；保留合传「合成一套分化」 | Admin `StudioPage.tsx` / `.css` |
| 多板块跟练 | **滚动一轮**（不要求连续天、不按周一重置）；文案「本套第 N/M 个板块」 | `api/.../plan_service.py` `get_following_progress` |
| 单板块 / 一日 | **只服务当天**：今日待练 / 进行中 / 已完成；隔日若已做过则**清跟练指针**（无进行中计划） | 历史场次保留；想再练需重新跟练 |
| 休息 | 软提示；大肌群约 3 天、小肌群约 2 天、核心可每天；跟练中也可记休息 | `todayHints.ts` / `TodayPage.tsx` |
| 退出跟练 | 今日「换计划 / 先不跟了」；确认文案强调**记录保留**；不自动因久未练退订 | `TodayPage.tsx` / `PlanDetailPage.tsx` |
| 台账 | 项目地图 §6 / §8 已更新跟练与工坊口径 | `docs/项目地图.md` |

### 1.3 数据模型（不变）

```
PlanTemplate（一套计划，如「三分化」）
  └── PlanBlock[]（有序板块：推日 / 拉日 / 肩腿）
        └── PlanExercise[]
Profile.active_plan_id + active_plan_started_at  → 跟练指针
TrainingSession.plan_template_id / plan_block_id → 场次溯源
```

字段名兼容：`week` / `week_cycle_done` 仍返回，**语义已是「当前轮」**，不是自然周。自然周只服务 dashboard「本周练了几天」。

### 1.4 明确不做（跟练周期）

- 不强制 A→B→C 顺序（仍可换板块）。  
- 不插入「休息日硬状态机」。  
- 退出/换计划**不得**删历史场次与组记录。  
- 三分化 ≠ 自动 `days_per_week=3`（频次以后台字段为准）。

## 2. 计划 vs 教练：并存规则（产品定调）

### 2.1 同一件事的两种入口

到「今天这场课」为止，计划和教练做的是同一类事：给你动作 → 你确认 → 开练。

| | 计划模板 | 教练今日课 |
|---|---|---|
| 有无现成多日结构 | 有 | 无（现拼） |
| 产出 | 选板块 expand → adopt | 对话草稿卡 → adopt |
| 生效时机 | 采纳/开练 | **仅当用户点采纳**；说话 ≠ 替换今日 |

### 2.2 跟练中找教练（简单版，本期采用）

**不做**「当前计划没有这个动作哦」硬拦，**不做**「改这场还是另开一桌」强制二选一审讯。

约定：

1. 教练照常出**今日草稿**（改动作、缩时间、加有氧、整场重排都行）。  
2. 用户**采纳** → `replace_today` 替换今日场次（现有 `adopt_draft` 行为）。  
3. **不自动 unfollow**；跟练指针仍在，下次今日仍可按跟练推下一板块。  
4. 问动作 / 闲聊 / 查数走 qa，不出新今日卡。  
5. 「知道你在跟哪套」= 可选软背景，**不是**门禁；与「知道当前草稿/今日场次」同类。

代价：偶尔今日实练与模板下一格不一致——可接受（用户主动找教练改的）。

### 2.3 不接 / 缓接

- 教练**检索计划库来排今日动作**：不需要（今日课仍走动作库工具）。  
- 久未练自动取消跟练：禁止（易被理解成丢记录）。

## 3. 待做 A：教练「荐模板」（出计划意图的小分类）

### 3.1 为什么要接

库里已有计划模板；用户说法不一定是「给我推荐个计划」，但同属「要一份可跟的安排」。  
与「排今天一场」分流，避免永远只出当日草稿。

### 3.2 意图分流

在 `plan` topic 下区分（名称可实现时再定字段）：

| 子类 | 典型说法 | 产出 |
|---|---|---|
| `today_session` | 今天练胸、只有 30 分钟、加个有氧 | `training_draft` → 采纳今日 |
| `recommend_plan` | 增肌计划、新手怎么练、有没有三分化、想跟博主那套 | **计划推荐卡** → 去详情 / 加入跟练 |

判不准时：先澄清芯片，**不要**直接出今日草稿。  
带「今天 / 这场 / 现在」倾向 `today_session`；带「计划 / 分化 / 跟练 / 四周」倾向 `recommend_plan`。

### 3.3 库驱动追问（禁止整句问卷写死）

「几乎没信息」时：

1. 读**已发布**计划，聚合真实筛选项：`scene_tag`、`level`、常见 `days_per_week`。  
2. 芯片**只出现库里有货的选项**（与 H5 `/plans` 分栏同源思路）。  
3. 用户点选 → 带条件检索 → 出 2～3 张模板卡。  
4. 库空或筛空 → 说明没有合适模板，fallback「先排今天一场」。

有一点倾向（「想增肌」）→ 可直接多卡对比，少追问。  
已很具体 → 滤后 1～3 张。

### 3.4 卡片形态

- **UI 与今日草稿卡同一套教练卡片语言**（标题、短说明、预览、主按钮）。  
- **主按钮语义必须分开**：  
  - 今日草稿 →「采纳为今日」  
  - 模板卡 →「去看这套 / 加入跟练」（进 `/plans/{id}` 或调 `follow`）  
- 荐模板**不**自动 adopt 今日场次；**不**偷偷 unfollow 旧计划（换跟走现有确认）。

### 3.5 实现要点（建议）

| 层 | 内容 |
|---|---|
| 意图 | `intent_rewrite` 增加子类或 `plan_kind`；评测补门禁用例 |
| 工具 | 新增如 `retrieve_plans`（只读已发布；按 scene/level/q）；**不要**塞进 `retrieve_exercises` |
| 图路由 | `recommend_plan` → 检索 + 出计划卡 / 澄清；与 `plan_loop` 今日排课并列 |
| H5 | Coach 渲染新 `card_type`（如 `plan_recommend`）；样式对齐 DraftCard，CTA 不同 |
| 反馈 | 气泡继续挂 `MessageFeedback` + `traceId`，差评进 inbox |
| 台账 | 落地后更新项目地图 §2–§5、§7–§8 |

### 3.6 风险（供评审盯）

- 「给我弄个增肌计划」歧义（模板 vs 今日课）。  
- 库过瘦时体验空。  
- 已在跟练时再荐：只多看，换跟需显式。

## 4. 待做 B：肌群可视化（两类，勿混）

### 4.1 动作详情 · 单动作发力示意（教程式、静态）

**目的**：这个动作练到哪（市面常见）。  
**数据**：SKU `muscle`（主）+ `roles`（协同）；字段要填齐。  
**落点**：`/exercises/:id`。  
**与动图关系**：示范 `aspect-square` **独占**，不叠图；标题/标签**下方**独立小节「发力部位」（小人体 + 主/协同说明），再接下要领。  
**不做**：今日清单、计划行每条塞小人（太吵）。

### 4.2 训练 tab · 全身热力（复盘式、动态）

**目的**：这段时间哪练得多/少。  
**数据**：已有 `TrainingDashboard.muscle_pulse`，无需新采集。  
**落点（修订工单旧结论）**：放在 **训练 tab「数据首页」**，与本周/月概览、图表**同级**，例如：

```
本周概览（环 + 时长/组数/PR）
本周部位（正/反面小热力）   ← 新增
PR 走势…
```

**不放**：

- 今日 Hero（今日只保留一句话部位间隔，决策用）。  
- 教练气泡里嵌大图（问答可用文字 + 链到训练 tab）。  
- 「我的」身体卡（那是体重等画像）。

记录页深链复盘可后期再挂同一组件；**首发可见性以训练 tab 为准**。

### 4.3 与教练关系

热力 / 动作示意 **不是**荐模板前置。教练被问「哪里薄弱」可先用 `muscle_pulse` 文字答，或引导去训练 tab。

## 5. 评测与反馈机制（坚持）

现有链路**保留**，继续喂 badcase：

```
Coach 气泡 MessageFeedback（up/down）
  → POST /api/feedback（差评带标签 + 快照）
  → FeedbackEvent.export_status=pending
  → api/scripts/export_feedback_inbox.py → eval/inbox
  → 人工晋级 → eval/ 正式绿集
```

注意：

- `web/src/feedback`（toast/loading）≠ 聊天气泡反馈。  
- 新对话能力（荐模板、数据问答增强）必须带 `traceId` + MessageFeedback。  
- 纯 UI（热力、动作小人）不靠气泡反馈；另补手测 / 必要时静态用例。  
- 改意图 / prompt 后按地图 §9：意图 → 长对话 → 整体。
