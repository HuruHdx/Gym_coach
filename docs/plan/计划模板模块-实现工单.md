# 计划模板模块 · 实现工单（交 Cursor）

> 目标：在现有「AI 出草稿 → 采纳落今日场次 → 按组打卡」链路之上，加一层**可后台配置的计划模板**：三 / 四分化等结构框架（槽位填充）+ 成品计划（动作锁定）。用户在 H5 浏览计划、选一个板块或整计划，展开成今日草稿再走现有打卡链路。
> 范围只做**训练计划**，不碰营养。
> 仓库：后端 + H5 在 `gym-coach`；后台配置台在 `gym-admin`。

---

## 0. 现有链路（复用，不要重造）

- AI 排课：`api/app/brain/plan_loop.py` 工具循环出草稿。
- 采纳落库：`POST /api/training/adopt` → `session_service.adopt_draft()`，写 `TrainingSession` + `TrainingSetLog`。
- 今日场次：`GET /api/training/today`；打卡改组：`PATCH /api/training/sets/{id}`；完成：`POST /sessions/{id}/complete`。
- 动作库：`Exercise`（`id/name_zh/name_en/muscle/gear/modality/roles/coach_core`），检索 `retrieve_exercises`。
- H5：今日 `TodayPage`、教练 `CoachPage`、动作库 `ExercisesPage/ExerciseDetailPage`；类型在 `web/src/types.ts`；接口封装 `web/src/lib/api.ts`。

**原则**：模板只负责「展开成草稿」，落地后的打卡、记录、1RM 回流全部复用现有场次链路，不在模板表里存训练进度。

## 1. 两类模板（先对齐概念）

| 类型 | 含义 | 动作来源 | 可替换性 |
|---|---|---|---|
| **框架型 `framework`**（三 / 四分化） | 只定分几天、每天部位、槽位角色、组次区间；动作待填 | 按部位 + 角色从动作库检索，LLM 结合个人情况（伤病 / 器械 / 偏好）选 | 槽位动作用户可换，结构（几天 / 部位）固定 |
| **成品型 `fixed`**（运动员 / 官方计划） | 动作、组数、次数、顺序都锁定 | 直接挂动作 SKU | 默认照搬；仅伤病 / 无器械 / 用户明确避免时降级替换 |

## 2. 后端：表结构定稿（`api/app/models.py`，✅ 已落地）

> 审核修订要点：`Exercise.roles` 仍是**中文肌群列表**（排课过滤用），槽位角色另开 `slot_roles`；时长用区间；热身用 `warmup_sets`；场次补模板溯源；展开**只按板块**成今日草稿（整计划 = 选板块）。

### 2.1 `PlanTemplate`（`plan_templates`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | str PK(32) | slug，如 `three-split-chest-back-legs` |
| `title` | str | 计划名（「热门三分化」「居家四分化」） |
| `subtitle` | str nullable | 副标题 |
| `author` | str nullable | 详情署名（「凯圣王 × 谭成义」） |
| `badge_label` | str nullable | 卡片角标（「谭成义」「加强版·新手勿练」），与 author 分开 |
| `template_type` | str(16) | `framework` / `fixed` |
| `level` | str(16) nullable | `beginner` / `intermediate` / `advanced` |
| `days_per_week` | int | 每周练几天 |
| `minutes_min` / `minutes_max` | int nullable | 单次时长区间（相等则展示「60 分钟」） |
| `muscle_tags` | JSON list[str] | 筛选用部位标签 |
| `split_summary` | str nullable | 卡片副文案（「胸 · 背 · 腿」）；空则用 muscle_tags 拼接 |
| `gear_tags` | JSON list[str] | 约定枚举：`杠铃/哑铃/壶铃/绳索/史密斯/固定器械/自重/弹力带` |
| `description` | str nullable | 简介正文 |
| `cover_url` | str nullable | 封面（横向图，落盘 `static/plans/`，**不要**走动作库 1:1 裁剪） |
| `is_published` | bool default False | 未发布不在 H5 展示 |
| `sort_order` | int default 0 | 列表排序 |
| `created_at` / `updated_at` | datetime | |

### 2.2 `PlanBlock`（`plan_blocks`，FK → template `ON DELETE CASCADE`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int PK | |
| `template_id` | str FK | 所属模板 |
| `order_index` | int | 板块序号 |
| `title` | str | 「胸肩三头」「腿 + 臀」 |
| `muscles` | JSON list[str] | 本板块部位 |
| `minutes_min` / `minutes_max` | int nullable | 本场时长区间 |
| `cover_url` | str nullable | 板块缩略图；空则接口用首个主项动作 thumb 兜底 |
| `note` | str nullable | 板块备注 |

### 2.3 `PlanExercise`（`plan_exercises`，FK → block `ON DELETE CASCADE`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int PK | |
| `block_id` | int FK | 所属板块 |
| `order_index` | int | 动作顺序 |
| `exercise_id` | str nullable | 挂 SKU；框架槽位可空 |
| `exercise_name` | str nullable | 冗余中文名 |
| `role` | str(16) | `main` / `assist` / `isolation` / `warmup`（独立热身动作） |
| `lock_level` | str(16) | `fixed` 锁定 / `slot` 可换 |
| `target_sets` | int nullable | 正式组数 |
| `target_reps` | str nullable | 如 `8-12`、`10` |
| `warmup_sets` | int default 0 | 正式组前热身组数（同动作递增热身，勿再拆行） |
| `alternatives` | JSON list[str] | 备选动作 ID/名 |
| `note` | str nullable | |

### 2.4 既有表补列（`_ensure_columns` + 启动预填，✅ 已落地）

| 表 | 字段 | 说明 |
|---|---|---|
| `exercises` | `slot_roles` JSON | 槽位角色；**不动** `roles`（肌群）。空值启动时按 `movement_pattern/gear/modality/coach_core` 启发式预填 |
| `trainingsession` | `plan_template_id` / `plan_block_id` / `plan_type` | 模板溯源；支撑今日主卡类型与「下次推荐下一板块」 |
| `trainingsetlog` | `is_warmup` bool default False | 热身组标记；不计入 1RM / 有效容量 |

### 2.5 动作槽位角色（后台编辑）

- 后台动作编辑台勾选写入 `Exercise.slot_roles`（取值同 §2.3 `role`）。
- 框架型检索按 `muscle + slot_roles` 过滤（查 DB，不改内存目录的 `roles` 肌群语义）。

## 3. 后端：接口（挂到 `/api` 公开读 + `/api/admin` 配置写）

### 3.1 H5 只读接口（`routers/plan.py`，新文件）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/plans` | 已发布模板列表；支持按 `type`、`muscle`、`level` 筛选；返回卡片字段（id/title/author/days_per_week/minutes/muscle_tags/gear_tags/cover_url） |
| GET | `/api/plans/{id}` | 模板详情：主信息 + 板块列表 + 每板块动作行（含角色 / 组数次数 / 锁定级别） |
| POST | `/api/plans/{id}/expand` | **必须带 `block_id`**：只把该板块展开成**今日单场**草稿（对齐 `AdoptRequest`；meta 含 sets/reps/muscle/role/warmup_sets，并回填 `suggest_weight_from_stats`）。框架型检索 + LLM 填槽；成品型直取锁定动作 |

展开后**不自动落库**，先回草稿给 H5 预览；用户确认采纳再调现有 `POST /api/training/adopt`（采纳时写入 `plan_template_id` / `plan_block_id` / `plan_type`）。  
「开始这个计划」= 选板块（多板块时抽屉点选；可按上次练完板块推荐下一个），**禁止**把整计划多日动作一次性塞进今日场次。

### 3.2 后台配置接口（`routers/admin.py` 增，`require_admin`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/plans` | 全部模板（含未发布），分页 |
| POST | `/api/admin/plans` | 新建模板主信息 |
| PUT | `/api/admin/plans/{id}` | 编辑主信息 / 上下架 / 排序 |
| DELETE | `/api/admin/plans/{id}` | 删除模板（级联删板块与动作行） |
| POST | `/api/admin/plans/{id}/blocks` | 新增板块 |
| PUT | `/api/admin/plan-blocks/{block_id}` | 改板块标题 / 部位 / 顺序 |
| DELETE | `/api/admin/plan-blocks/{block_id}` | 删板块 |
| POST | `/api/admin/plan-blocks/{block_id}/exercises` | 加动作行（选 SKU 或留槽位） |
| PUT | `/api/admin/plan-exercises/{ex_id}` | 改动作行角色 / 组次 / 锁定级别 / 备选 |
| DELETE | `/api/admin/plan-exercises/{ex_id}` | 删动作行 |

### 3.3 展开规则（`services/plan_expand.py`，新文件）

- **成品型 `fixed`**：直接读 `PlanExercise`，`exercise_id` 存在则带 SKU；组次取 `target_sets/target_reps`；热身组标 `is_warmup`。
- **框架型 `framework`**：
  1. 按板块 `muscles` + 动作行 `role` 调 `retrieve_exercises` 取候选；
  2. 结合档案 `injuries / avoid_exercises / gear / preferences` 过滤；
  3. LLM 在候选里选动作填槽位（复用 PLAN 工具循环思路，不新造模型链路）；
  4. 填不出的槽位保留为空，草稿里标注「待补充」，不硬塞动作。
- 降级：成品动作命中伤病 / 缺器械时，从 `alternatives` 找替代；找不到则保留并在备注提示。

## 4. 后台 `gym-admin`：配置台

### 4.1 导航与路由
- `AdminShell` NAV 加一项「计划模板」`/plans`；`App.tsx` 挂路由。
- 页面：`PlansPage`（模板列表 + 新建）、`PlanDetailPage`（板块与动作行编排）。

- 动作角色勾选：在动作 SKU 编辑台补一组角色标签（main/assist/isolation/warmup），写 `Exercise.roles`。

## 7. 验收标准

- 后台能新建模板、编排板块与动作行、上传封面、上下架；刷新后数据持久。
- H5 列表只显示已发布模板；详情能看到板块分组与动作清单。
- 选成品计划展开 → 草稿动作 / 组次与后台配置一致；采纳后进入今日场次，可正常打卡。
- 选框架计划展开 → 槽位按部位 + 角色检索填充，伤病 / 避免动作被排除；填不出的槽位有标注，不硬塞。
- 现有 `pytest` 全绿；AI 对话出计划、打卡、记录、1RM 回流无回归。
- 未发布模板不在 H5 出现；删除模板级联清理板块与动作行。
