# 上班机器环境准备（交 Cursor 执行）

> 场景：在公司电脑上继续开发 Gym Coach，**看不到界面效果**，只写代码 / 跑测试 / 改文档。
> 结论：**不需要安装 PostgreSQL，不需要 pgAdmin，不需要 pg_dump**。后端测试用内存 SQLite，本地跑全站也可以直接用 SQLite 文件。
> 执行原则：每一步先**检查**，缺什么装什么，已装则跳过。

---

## 0. 先决条件

- 系统：Windows
- 两个仓库地址（公司电脑直接 clone 到同一父目录，建议并排放）：

  ```powershell
  git clone https://github.com/HuruHdx/Gym_coach.git      # H5 + 后端
  git clone https://github.com/HuruHdx/Gym_coach_Admin.git # 后台工作台
  ```

- 无需管理员权限的部分优先；需要装系统级工具时用 `winget`（若 `winget` 不可用，改用官方安装包）
- 两个仓库的默认分支都是 `main`

---

## 1. 环境检查与安装（按顺序执行）

### 1.1 检查工具是否已存在

```powershell
Get-Command uv, node, npm, pnpm, git -ErrorAction SilentlyContinue | Select-Object Name, Source
```

逐个确认输出。**只对缺失的那一项执行安装**。

### 1.2 安装 uv（Python 依赖与虚拟环境）

```powershell
if (-not (Get-Command uv -ErrorAction SilentlyContinue)) {
    winget install --id astral-sh.uv -e --accept-source-agreements --accept-package-agreements
}
```

装完后需重开终端，再验证：

```powershell
uv --version
```

> 若 winget 装不上，备用方式：
> `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`

### 1.3 安装 Node.js LTS 与 pnpm（前端依赖）

```powershell
if (-not (Get-Command node -ErrorAction SilentlyContinue)) {
    winget install --id OpenJS.NodeJS.LTS -e --accept-source-agreements --accept-package-agreements
}
```

重开终端后：

```powershell
node --version
npm --version
```

pnpm 优先用 corepack 启用（Node 自带）：

```powershell
if (-not (Get-Command pnpm -ErrorAction SilentlyContinue)) {
    corepack enable
    corepack prepare pnpm@latest --activate
}
pnpm --version
```

> 若 corepack 不可用，回退：`npm install -g pnpm`

### 1.4 git 身份（只配置一次）

```powershell
git config --global user.name    # 应有输出
git config --global user.email   # 应有输出
```

缺失时补充（用你自己的名字与邮箱）：

```powershell
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
```

**不要安装**：PostgreSQL、pgAdmin、pg_dump、Docker（本期无需）。

## 2. 后端：配置 SQLite 并跑测试

### 2.1 创建 `api/.env`

`gym-coach/api/.env` 已被 `.gitignore` 忽略，需要在本机手工创建（**不要提交**）：

```
DATABASE_URL=sqlite:///./data/gym.db
APP_TOKEN=dev-token
LLM_PROVIDER=mock
```

说明：
- 用 SQLite 是为了**零安装**、随仓库即可跑，不影响写代码与跑测试；
- 家中机器用 Postgres（`postgresql+psycopg://...`），两边 `.env` 各自独立，互不影响；
- 公司机器不要填真实 LLM Key，用 `mock` 即可。

### 2.2 安装依赖

```powershell
cd gym-coach/api
uv sync
```

### 2.3 跑测试（验收门槛）

```powershell
uv run python -m pytest -q
```

期望：**196 passed**（数字会随新增用例增长，重要的是 `0 failed`）。

> 若 `uv run pytest` 报 `uv trampoline failed to canonicalize script path`，改用 `uv run python -m pytest -q`。

### 2.4 可选：起服务验证表结构

```powershell
cd gym-coach/api
uv run uvicorn app.main:app --reload --port 8000
```

启动时会自动 `init_db()`：
- 新表 `plan_templates` / `plan_block` / `plan_exercises` 自动建出；
- 老表补列走 `db.py._ensure_columns()`。

浏览器打开 `http://127.0.0.1:8000/docs` 可确认服务活着（不验证业务界面）。

### 2.5 可选：导入动作库（需要调检索效果时）

```powershell
cd gym-coach/api
uv run python scripts/import_opengym_exercises.py
```

从 `api/assets/opengym/opengym_exercises_enriched.json`（随仓库提供）导入 5600+ 动作。SQLite 下同样可用。

## 3. 前端：只装依赖，不要求看效果

```powershell
cd gym-coach/web
pnpm install
```

验证类型/构建（不需要起 dev server）：

```powershell
pnpm build
```

> 只写页面骨架、类型、接口封装时，`pnpm build` 或 `tsc --noEmit` 足以发现问题。

## 4. 后台 `gym-admin`

```powershell
cd gym-admin
npm install
npm run build
```

同样的 `.env`（`VITE_API_BASE`）已在 `.gitignore` 中忽略，需要时手工创建：

```
VITE_API_BASE=http://127.0.0.1:8000
```

---

## 5. 禁止事项（避免污染仓库）

- 不提交 `api/.env`、`gym-admin/.env`；
- 不提交 `api/static/exercises/`（100MB+ 素材图）；
- 不提交 `api/data/`（本地库文件）、`web/node_modules`、`web/dist`；
- 不安装 PostgreSQL / pgAdmin；
- 不改 `db.py._ensure_columns()` 之外的建表方式（新表靠 `create_all`）。
