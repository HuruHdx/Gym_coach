## Phase 1：教练「荐模板」闭环（方案 §3）

**目标**：让用户在对话里索要「多日计划 / 增肌计划 / 新手怎么练 / 有没有三分化」时，能正确分流到模板推荐，并以独立卡片形式浏览详情或加入跟练，而不污染今日排课草稿状态机。

### 1.1 任务清单

1. **意图槽位增加 `plan_kind` 分流**
   - 文件：`api/app/brain/intent_rewrite.py`
   - 改动：
     - 新增常量 `ALLOWED_PLAN_KINDS = {"today_session", "recommend_plan"}`。
     - 更新 `INTENT_REWRITE_SYSTEM`：在 `topic="plan"` 下要求输出 `plan_kind`：
       - `today_session`：要排今天/这一场的训练（含「今天 / 这场 / 现在 / 只有 30 分钟 / 练胸 / 改草稿」）。
       - `recommend_plan`：要一套多日课表/长期规划/模板（「增肌计划 / 新手怎么练 / 有没有三分化 / 推荐一套计划 / 想跟博主那套」）。
       - 对已有草稿的 `draft_relation in ("confirm", "revise", "fresh")` 默认维持 `today_session`。
     - **关键防冲突改造**：检查 `_stick_to_open_plan` 和 `apply_coach_routing`（特别是 `_is_blank_plan` 与「老炮大部位追问 `focus`」分支），当 `plan_kind == "recommend_plan"` 时**跳过今日课的反问规则**，交由推荐分支处理。

2. **新增模板检索与库驱动澄清逻辑**
   - 文件：建议新建 `api/app/brain/plan_recommend.py`（或拆在 `plan_service.py` + `brain/graph.py`），**不要把计划模板查询塞进 `tools.py` 的 `retrieve_exercises`**。
   - 功能点：
     - `retrieve_plans(session, *, scene_tag=None, level=None, days_per_week=None, muscles=None, q=None, limit=3)`：只查 `PlanTemplate.is_published == True`；按匹配度排序返回最多 3 张模板摘要（含 `id`, `title`, `subtitle`, `scene_tag`, `level_label`, `days_per_week`, `minutes_label`, `split_summary`, `muscle_tags`, `cover_url`）。
     - `aggregate_plan_facets(session)`：统计当前所有已发布计划的真实 `scene_tag`、`level`、`days_per_week` 分布。
     - **低库存短路与追问策略**：
       1. 若全库已发布计划 **≤ 4 套**，或带当前已知条件初筛后候选 **≤ 3 套**：**跳过追问**，直接输出命中卡片（由 LLM 或轻量模板生成一句说明各自适合谁）；
       2. 若库内可选多且用户意图极模糊（无 goal/scene/days/split 约束）：仅从 `aggregate_plan_facets` 中有 2 个及以上可选项的维度生成 3～4 个澄清芯片（点击后直接带条件检索）；
       3. 若库空或过滤后 0 命中：明确告知「库里暂时没有完全匹配的现成计划」，并提供 fallback 芯片（如「按你的情况排今天一场」→ 触发 `today_session`）。

3. **图路由接入与独立卡片契约 `plan_recommend`**
   - 文件：`api/app/brain/graph.py`、`api/app/brain/memory_context.py`、`api/app/schemas.py`
   - 改动：
     - `_pick_route`：当 `topic == "plan"` 且 `domain != "nutrition"` 且 `plan_kind == "recommend_plan"` 时，路由到新分支（如 `"recommend"`），不进入 `plan_loop`（动作库循环）和 `validate_node`（动作校验）。
     - 输出卡片结构 **强制使用 `card_type: "plan_recommend"`**（严禁复用 `training_draft`）：
       ```json
       {
         "kind": "card",
         "card_type": "plan_recommend",
         "title": "为你挑了 2 套可跟计划",
         "status": "draft",
         "items": [
           {
             "id": "plan-three-split-classic",
             "title": "热门三分化",
             "subtitle": "每周 3 天 · 50-75 分钟 · 胸肩 / 背臂 / 腿臀",
             "selected": true,
             "meta": {
               "plan_id": "three-split-classic",
               "scene_tag": "热门计划",
               "level_label": "进阶",
               "days_per_week": 3,
               "minutes_label": "50-75 分钟",
               "split_summary": "胸肩 · 背臂 · 腿臀",
               "cover_url": "..."
             }
           }
         ],
         "actions": []
       }
       ```
     - **上下文隔离**：`memory_context.py`（`render_turn` / `format_short_term` / `build_intent_context`）识别当气泡卡片为 `plan_recommend`（或 `exercise_ref`）时，**不要把它当成「今日待改动作草稿」**传给下一轮的 `draft_title` / `draft_items`。

4. **H5 渲染推荐卡与反馈标签**
   - 文件：新增 `web/src/components/PlanRecommendCard.tsx`，更新 `web/src/pages/CoachPage.tsx`、`web/src/components/MessageFeedback.tsx`、`web/src/types.ts`
   - 改动：
     - `CoachPage.tsx` 在渲染 `m.card` 时新增分支 `m.card.card_type === "plan_recommend"` → 渲染 `PlanRecommendCard`。
     - `PlanRecommendCard.tsx` 视觉对齐 `DraftCard` 边框/圆角/字体体系，但主按钮明确区分：
       - 次按钮：**查看详情**（`navigate("/plans/" + planId)`）
       - 主按钮：**加入跟练**（调用 `POST /api/plans/{planId}/follow`；若当前已跟练另一套计划，先弹确认「将切换跟练计划为《X》，原计划历史保留」，**不自动覆写今日场次**）。
     - 气泡继续挂载 `MessageFeedback`（带 `traceId`）。按需在 `DOWN_TAGS` 中确认或补充推荐场景标签（如保留 `bad_plan` 或新增 `bad_recommend` 并在 `api/app/schemas.py` `FEEDBACK_TAGS` 同步白名单）。

5. **补齐评测用例**
   - 文件：`eval/cases-intent.yaml`、`eval/assertions/`（按需扩展 `intent.js` / `topic.js`）、`api/tests/test_intent_rewrite.py`
   - 新增门禁用例覆盖：
     - 明确今日：`今天练胸` / `只有30分钟帮我排一下` → `today_session`
     - 明确模板：`有没有三分化` / `新手怎么练` / `推荐个增肌计划` → `recommend_plan`
     - 歧义句：`给我弄个增肌计划` → 允许先澄清或分流，确保不误伤今日排课已有用例。

## Phase 4：教练「查数 / 体感 / 复盘」加深（AI 能力进阶）

**目标**：盘活已有的 `ExerciseStats.last_feeling`、`estimate_1rm`、`muscle_pulse` 和 `build_session_compare`，让 AI 教练真正基于用户近期表现排负荷、答进度、做练后复盘。

### 4.1 任务清单

1. **排课工具吃进主观体感与 1RM 基准**
   - 文件：`api/app/brain/tools.py`、`api/app/brain/memory.py`（`_format_stat_line`）、`api/app/brain/plan_loop.py`
   - 改动：`tool_get_related_stats` 的 `hits` 与 `_format_stat_line` 补入 `last_feeling`（轻松/合适/力竭）、`last_outcome`、`estimate_1rm`；在 `PLAN_TOOL_SYSTEM` 补充规则：若上次 `last_feeling == "轻松"` 且 `last_outcome == "达标"`，可建议小幅渐进加重或加次数；若 `last_feeling == "力竭"` 或 `last_outcome == "没做完"`，保持或略降负荷。

2. **数据问答（`recall` / `decide`）接入 `muscle_pulse` 与周节奏**
   - 文件：`api/app/brain/graph.py`、`api/app/brain/knowledge_reply.py`
   - 改动：
     - 放宽 `graph.py` 里仅靠 `_MEMORY_CUES` 硬匹配死模板的限制；当 `qa_kind in ("recall", "decide")` 且涉及「哪里练得少 / 最近进度 / 练没练 / 明天练啥」时，注入 `analytics_service.build_muscle_pulse` 与 `build_week_rhythm` 摘要；
     - 在无历史记录时严守「没有记录不编数字」红线。
