## 2. 今日页 `web/src/pages/TodayPage.tsx`

### 2.1 「本周」格（P2）→ 移出今日页

**结论：本周进度不属于今日页，移到 `/training`。**

理由：今日页只回答"今天练什么"。"这周练了几次"是周维度总结，和今天的决策无关；现在它还和 Hero 第一行的"本周第 1/3 练"重复表达同一件事。

**改为在 `/training` 顶部放一条周进度**（7 段横向条 + `2 / 3 练 · 共 38 组`），今日页删掉这一格。数据源仍是 `GET /api/training/week`（§5.1）。

**如果暂时不想动 `/training`**：今日页这一格先只保留一句纯文字 `本周已练 2/3`，不铺进度条，避免和 Hero 抢注意力。

### 2.2 「部位间隔」格（P2）→ 留在今日页，改形态

**现状**：L634-639，空态文案。

**改为**：一句话结论，不是报表。

```
今天建议练腿 · 距上次 6 天
胸 3 天 · 背 1 天 · 腿 6 天
```
- 第一行给结论（取间隔最长且已过阈值的部位），第二行才是明细
- 点色规则：大肌群（胸/背/腿）间隔 48h，小肌群（肩/臂/核心）24h；超间隔绿点，未到灰点
- 数据源：`GET /api/training/muscle-gap`（§5.2）
- **文案禁止出现"恢复 / 未恢复"**，只写"部位间隔 / 距上次 N 天"
- 只统计 `completed=true` 且 `is_warmup=false` 的组
- 没有任何历史时整块隐藏，不要留空态占位

**结论句由规则算，不走 AI。** 判定顺序固定：

1. 取各大肌群 `days_since`，过滤掉未过阈值的（未到 48h/24h 不算"该练了"）
2. 候选里取 `days_since` 最大者作为建议部位
3. 无候选 → 改成 `隔得最久的是 X，已经 N 天`（此时不构成"建议"，只是事实）
4. 完全没有历史 → 整块隐藏

理由：
- 规则可复现、秒出、零成本，且结论永远和数据一致
- AI 写一段话容易编原因（"你上周练腿很累"这类它其实看不到的信息），在健身场景里等于给错建议
- 想做句式变化就准备 3–5 个模板轮换，别交给模型

**唯一可以上模型的场景**：判断"今天该不该减量/休息"——那要看负荷趋势，规则算不了。但当前没有足够数据（无 RPE、无心率、无单次强度曲线），**这一期不做**。

### 2.3 「上次」卡（P2）→ 移出今日页

**结论：不放在今日页。**

「上次」回答的是"上回练成什么样"，属于复盘，和"今天练什么"是两个问题。放今日页只会把首屏变成数据面板。

**改为落在 `/training/records`**（列表顶部一张，或每场详情里），不复用今日页位置。数据契约见 §5.3，前端逻辑不变。

### 2.4 每组行「上次 N 次」（P2）

**现状**：训练中每组行无历史对照。

**改为**：
```
第 3 组  60kg × 8          上次 8 次      [完成]
```
- 数据：同 `exercise_name` + 同 `set_index` 的最近一次 `actual_reps`（§5.4）
- 无历史则整段隐藏

### 2.5 组间休息倒计时 —— 不做

**决定：不做。**

理由：
- 组间休息时人不看手机，盯着倒计时没有使用场景
- 页面已有整场计时器（`timer_started_at` + `elapsedSeconds()`，L51-56 / L1041），一个钟够用
- 加组间倒计时要多维护一套状态（localStorage、切页不丢、跨场清残留），收益不抵成本

**`rest_sec` 字段保留**，不删：
- 它是未来视频分析 / 疲劳判断 / 实际组间间隔测算的基础（`completed_at` 已经在记，两个配合能算出真实组间）
- 后台配置计划时仍可填，只是 H5 暂时不渲染计时 UI

> 如果以后真要做，只做一个极轻的提示（勾完一组后 Toast 一行"歇 90 秒"），不做常驻计时器。

### 2.6 休息日态（P1 口径 + 样式收尾）

**判定优先级**（命中即停）：
1. 当天存在 `source="rest"` 的 session → 已记录休息日
2. 当天无 session 且本周已达标（`done_sessions >= target`）→ 建议休息
3. 当天无 session 但未达标 → 正常推课，不算休息日
4. 其余 → 正常推课

**文案**（不要写成"系统判定你必须休息"）：
```
休息 · 建议
这周够了，歇一天也行
本周 3 练已达标，昨天刚练腿。
[明天：背 + 二头] [想练也可以，随时能开]
[记今天休息] [还是想练]
```
- `记今天休息` 写入：`source="rest"`, `status="done"`, `total_volume=0`, 0 组
- 所有统计口径排除 `source="rest"`

### 2.8 计划卡：最多 4 张 + 卡数自适应

**现状**：`plans.slice(0, 2)` 固定 2 张，`TodayPage.tsx` L649 起。

**改为**：2 列网格，最多 4 张，标题行右侧 `全部 ›` 跳 `/plans`。

**关键：按已发布模板实际数量自适应，不硬凑 4 张。**

| 已发布模板数 | 排布 |
|---|---|
| 2 | 2 列，卡片加高到 ~200px，不留大片空白 |
| 3 | 2 + 1；末张可通栏 |
| 4 | 2×2，每张约 140px |
| ≥5 | 显示前 4 张 + `全部 ›` |

原因是库里现在只有 2 个已发布模板（`three-split-classic`、`fixed-push-strength`），五分化与新手入门模板尚未落地。设计按 4 张做，实现按 `min(4, 已发布数量)` 渲染并让卡高自适应，**不要为了填满去造假模板或占位卡**。

**卡片视觉**（与 §2.13 一起改）：
- 有 `cover_url`：深色蒙版 + 图，白字
- 无 `cover_url`：深色兜底底（`linear-gradient(160deg, #2a2536, #17161c)` 一类），白字始终可读
- 标签（场景 / 新手指）左上角胶囊，标题 13.5px/700，副标题 9.5px/白 72%

### 2.9 「一句话改课」收进 Hero，不再单独占一栏

**现状**：`TodayPage.tsx` 底部独立一栏三个 chip「今天只有30分钟」「练胸·器械优先」「按上次记录续排」。

**问题**：看起来像筛选标签，实际是发指令；chip 宽度随句子长短参差；单独占一栏但只有三句固定话术，扩展不了。

**改为**：删掉独立区块，在 Hero 卡底部放一行文字链：

```
时间 / 器械不一样？改一下 ›
```

点开弹 sheet，里面是那三个预设 + 自由输入；提交仍走现有教练链路。

**备选**：整块删除，改课一律进 `/coach`。若删，Hero 只剩「开始这场 / 换个板块」，页面更干净但高频的"只有30分钟"要多跳一步。**默认采用文字链方案。**

### 2.10 今日页五态：一个路由，五种样子

`/` 不是"一页静态内容"，而是按"今天有没有课、课从哪来、开没开始"切换版式。**态之间要差得足够大，不能只是换个标签。**

| 态 | 判定 | 首屏主体 | 右上角 | 不该出现 |
|---|---|---|---|---|
| **A 未定课** | 今天无 session，且无跟练计划 | Hero「今天还没课」+ 让教练排 / 挑一套 + 计划卡 | `换计划` | 计时、组列表 |
| **B1 模板采纳** | 今天有 session、`status=active`、`timer_started_at` 空，来源=模板 expand | Hero「腿臀」+ `热门三分化 · 第 3 个板块` + 首个动作上次 + `开始这场` / `今天想练别的？` + `这场做什么` 清单 | `换计划` | 计划卡（已有课，不再让人逛） |
| **B2 教练定制** | 同上，来源=对话草稿采纳 | 同 B1，但来源行改 `教练排的 · 按你今天的状态`，并多一句教练原话（引语） | `重新排` | 同上 |
| **C 训练中** | 今天有 session、`timer_started_at` 有值 | 当前动作大卡 + `完成这组` + 计时 + 下一个 + 本场动作清单 | `结束这场 ›` | **计划卡、部位间隔、改课入口** |
| **D 已完成** | `status=done` | 这场小结（组数/总重量/时长）+ 下次练什么 + 动作回顾 | 不显示 | 计时、完成按钮 |

对照图：桌面 `04-今日页-五态对照.png`（A / B1 / B2 / C / D 五屏并排）。

**B1 与 B2 必须区分来源**，这是真实差异：用户要知道这课是模板给的还是教练按今天状态排的。B2 多一句教练原话（来自草稿 summary），这是它唯一比 B1 多的信息，也是最值钱的那句。

**B 态必须放「这场做什么」清单**（动作名 + 组×次）。实测首屏如果不放，Hero 下面会空掉一大截；而且开始前看到今天练哪几个动作，本身就比任何统计有用。

实拍确认：现有代码在 B/C/D 已经切换 Hero（`TodayPage.tsx` L244 起，标签 `执行中 / 已完成`），但存在三个问题：

1. **C 态没有焦点**：整页平铺所有动作 + 所有组，用户不知道该做哪一组；应改成"当前动作 + 完成这组"为主视觉，动作清单降为次要
2. **C 态仍露出计划卡和部位间隔**：训练中不该出现"想换一套"这类浏览内容
3. **C 态顶部还有「换计划」入口**：训练中应该是「结束这场」，换计划只在 A/B 出现

C 态的目标版式（见桌面 `03-今日页-训练中.png`）：

```
执行中                      12:34
平板杠铃卧推                  ← 当前动作，26px
第 2 组 / 共 4 组 · 60 kg × 8 次 · 上次 8 次
[完成这组]                   ← 唯一实心，全页最亮
8 / 16 组 · 50%      还剩 2 个动作
─────────────────────────
下一个 · 上斜哑铃卧推  3 组 · 24 kg × 10  ›
─────────────────────────
本场动作                    排序
✓ 平板杠铃卧推      4/4
● 上斜哑铃卧推      1/3     ← 进行中，紫
○ 坐姿哑铃推举      0/3
```

要点：
- 「完成这组」是 C 态唯一实心主按钮，与 B 态的「开始这场」接力，全页始终只有一个实心按钮
- 「上一个/下一个」不要各占一块，只留"下一个"，上一条已在清单里打勾
- **「换个板块」改文案为「今天想练别的？」**：现在这个词用户不知道"板块"是什么；且点击应就地弹出板块列表（三分化 3 个板块），而不是跳 `/plans/{id}` 再选一次

### 2.11 「结束这场」放右上角，不放底部

**决定：右上角，灰字小号，点击弹二次确认。**

理由：
- 训练中的主操作是「完成这组」，结束是收尾/退出，不是并列操作
- 放底部显眼会跟「完成这组」抢注意力，**练到力竭时手抖极易误触**，一点就中断整场
- 底部已有 tab bar 占位，再摆一个显眼按钮会出现两个"出口"
- 右上角符合"关闭/结束在右上"的系统习惯

样式与交互：
- 灰字（`#8e8ba3`）、12px、不加底色，**不要红色**（红色像删除，会被当成危险操作而被回避）
- 点击必弹确认：`结束这场？还有 8 组没做，会记为未完成`
- 只出现在 C 态；A/B 态右上角是 `换计划` / `重新排`，D 态不显示

### 2.12 连续训练天数与「建议休息」的提示

**可行，数据全在 `trainingsession`，纯查询。但不要按"日历连续天数"算。**

按连续天数会失效：三分化本来就是隔天练，日历连续 5 天几乎不会出现，这个提示等于永远不触发；而天天练的人又会被每天弹一次，三天后就无视了。

**改三种触发，都能从现有表算出：**

| 触发 | 条件 | 文案 |
|---|---|---|
| 同部位连续受训（**最该拦**） | 同一大肌群连续 2 天以上有训练 | `胸连着练了 2 天，明天换个部位或休息` |
| 本周达标 | `本周已练 ≥ 计划次数` | `这周够了，歇一天也行` |
| 连续无休 | 连续有训练的天数 ≥ 6 且中间无 `source=rest` | `连着练了 6 天，今天建议休息` |

**展示形态**：只在真的越界时出现，放在部位间隔那句下面一行文字（紫/橙小字），不做横幅、不做弹窗、不做红点。没有触发时完全不占位。

**不要做的**：每日固定弹"建议休息"。健康 App 的通病就是天天劝休息，用户会当作背景噪音直接无视。

另外注意 `source="rest"` 的场次要参与"连续无休"的计算（记了休息就重置 streak），但不计入"本周已练"。

### 2.13 实机发现的两个视觉 bug（必修）

**a) 计划卡无封面 → 白字压浅底，标题看不见**

`TodayPage.tsx` L659-674：`cover_url` 为空时背景走 `bg-gradient-to-br from-[var(--hero-a)] via-bg to-bg`（浅紫→浅底），但卡片文字固定 `text-white` / `text-white/70`。实测两张计划卡（热门三分化、经典五分化）的标题几乎不可见。

二选一：
- **A（推荐）**：无封面时用深色兜底底 `background: rgba(23,22,28,.80)`，保证白字可读
- B：文字颜色跟着 `cover_url` 走，无图时改用 `text-ink` / `text-muted`

**b) Hero 两个分母撞车**

实测首屏同时出现：

```
热门三分化 · 本周第 1/3 练     ← 分母 = 每周练几次
...
第 3 / 3 个板块                ← 分母 = 模板板块数
```

两个 `3` 含义不同，用户无法分辨哪个是进度。

改法：
- 第一行只留 `热门三分化`，删掉 `本周第 N/M 练`（周进度归 `/training`，见 §2.1）
