## 模块 1：支持「今日第二练 / 多练」（不作废已完成场次）

### 1.1 现状问题
- `api/app/services/session_service.py`：
  - `adopt_draft` 在 `replace_today=True` 时遇到今日有 `done` 场次会返回 `409`，只有 `force_replace_done=True` 时才会走，但会调用 `abandon_today_done` 把今天刚练完的那场**标为 `abandoned` 作废**；
  - `add_exercise_to_today` 在今日只有 `done` 无 `active` 时直接 `409` 拒绝。
- `web/src/components/DraftCard.tsx`：当 `todayStatus === "done"` 时，主按钮变成「覆盖今日已完成场次并重新采纳」。
- `web/src/pages/TodayPage.tsx`：进入 `isDone`（D 态 Hero）后没有「再练一场 / 加练」入口。

### 1.2 改造方案（拍板口径 2026-11-27）

**状态机（必须遵守）**

| 今天状态 | 再开练 / 采纳 / 加动作 | 行为 |
|---|---|---|
| 有 `active`（未完成） | 开新计划 / 重新采纳 | **覆盖**：二次确认后 `abandon` 当前 active，再新建一场；**不**并行两条 active |
| 仅有 `done`（无 active） | 「再练一场」/ 第 2 练采纳 / 动作库加入 | **追加**：保留已完成记录，新建 `active`；今日页只盯当前场，旧场进历史 |
| 仅有 `done` | 显式「覆盖已完成」 | `force_replace_done`：作废今日 done 后重开（次要入口 + 二次确认） |

1. **后端（`schemas.py` & `session_service.py` & `plan_service.py`）**
   - `AdoptRequest` 新增 `append_today: bool = False`（保留 `replace_today` / `force_replace_done`）。
   - `adopt_draft`：`append_today=True` 时不 409、不 abandon done/active，直接新建 `active`；`replace_today=True` 仍先 `abandon_today_active`（未完成强行清掉），仅 `force_replace_done` 才 abandon done。
   - `add_exercise_to_today`：无 active 仅有 done 时**不再 409**，自动新建 `split_label="加练"` 的 active 并写入。
   - `get_today_active`：**优先最新 active**；无 active 再取最新 done。
   - `get_following_progress`：同天若存在 active，进度文案优先「今日进行中」（即使更早有 done）。

2. **前端**
   - `DraftCard`：`done` → 主按钮「作为今日第 2 练开练」(`append_today`)；覆盖已完成收进次要链 + 确认；`active` → 确认「取消当前未完成并重新开练」。
   - `TodayPage` D 态：可显示当日完成场次数；入口「再练一场」（跟练下一板块 / 去教练）。
   - `ExerciseDetailPage`：加入今日在 done 后直接开加练成功，去掉阻碍文案。

### 1.3 验收标准
- [x] 上午完成一场胸训（`done`）后，下午从教练页点「作为今日第 2 练开练」或从动作详情点「加入今日训练」，今日页切入新的 `active` 场次；
- [x] 完成第 2 练后，训练记录列表与 `TrainingDashboard` 同时计入两场（容量、组数、部位均不丢失第 1 练）；
- [x] `pytest tests/test_multi_session_today.py tests/test_training.py tests/test_plans.py tests/test_analytics.py` 全绿。

## 模块 2：`PlanRecommendCard` 状态显性化与可切换（不整卡作废）

### 2.1 现状问题
- `web/src/components/PlanRecommendCard.tsx` 目前使用 `const cardSpent = Boolean(activePlanId)`：只要用户当前有正在跟练的计划，推荐卡整张变灰并隐藏按钮、显示「已有跟练中的计划，这张推荐不再使用」。用户练完回到教练页时，既看不出自己当初选了哪套，也无法切换到同卡里的其他候选。

### 2.2 改造方案（拍板：选完即废，只可查看）
- **文件**：`web/src/components/PlanRecommendCard.tsx`
- **口径**：聊天荐卡是「当场选一套」；选完 / 已有跟练后本卡**结束加入**，只可查看；换计划去计划库/详情，不在气泡里切换。
- **改动**：
  1. 保留 `cardSpent = Boolean(activePlanId)`：已有跟练则隐藏所有「加入跟练」；
  2. 逐条标出当前跟练：`isCurrent` → **「✓ 跟练中」** + 描边，避免「整卡糊成一团看不出选了谁」；
  3. 已花费时每条只留 **「查看详情」**；未花费时仍是「查看详情」+「加入跟练」。

### 2.3 验收标准
- [x] 未跟练时可加入；加入后该条亮「✓ 跟练中」，同卡其它候选只可查看、不能再加入/切换；
- [x] 文案说明「已选定，换计划去计划库」；
- [x] 换跟练不在聊天卡完成（计划库/详情）。

## 模块 3：标准化人体肌肉解剖结构图 SVG（替换几何块与文字方块）

### 3.1 现状问题
- `web/src/components/dashboard/MuscleHeatmapCard.tsx` 当前使用椭圆 + 梯形几何拼接，视觉粗糙；
- `web/src/components/MuscleFocusDiagram.tsx` 当前仅用一个写着主练肌名字的小方块占位，缺少直观人体位置示意。

### 3.2 改造方案
- **新增共用组件**：`web/src/components/BodyAnatomySvg.tsx`
- **图形设计要求**：
  1. 采用**标准化矢量正面 + 背面人体轮廓与肌肉解剖分片 SVG Path**（参考开源肌肉解剖矢量路径体系如 `react-body-highlighter` 风格精简重构，无外链图片、纯内联 SVG `<path>`）；
  2. 包含流畅外层人体剪影（`silhouette`）与精细解剖分区 path，并能稳定映射到系统内的中文肌群枚举：
     - 正面：`胸`（胸大肌）、`肩`（三角肌前/中束）、`臂`（肱二头、前臂）、`核心`（腹直肌/腹斜肌）、`腿`（股四头肌、小腿前侧）；
     - 背面：`肩`（三角肌后束）、`背`（斜方肌、背阔肌、竖脊肌）、`臂`（肱三头、前臂）、`腿`（臀大肌、腘绳肌、小腿后侧）；
  3. 颜色严格走 `gym-ui/tokens.css` CSS 变量（`--accent`、`--line`、`--surface`、`--text-3`），支持深浅色主题切换不糊字、不写死硬编码亮色。
- **两处复用**：
  1. **`MuscleHeatmapCard.tsx`（`mode="heatmap"`）**：
     - 替换原有几何块 SVG；支持正/反面并排（或切换）展示，按 `count_30d / maxCount` 分 4 档填充 `--accent` 透明度阶梯；点击身体区域可直接选中该大肌群并高亮轮廓边框。
  2. **`MuscleFocusDiagram.tsx`（`mode="focus"`）**：
     - 替换原有的纯文字方块；左侧放紧凑的正/反面解剖双小人（自动高亮 `primary` 主练肌为强强调色、`secondary` 协同肌为浅一档强调色，只亮真正参与的正面或背面对应区域），右侧保留 `主练 / 协同` 标签与文字说明。

### 3.3 验收标准
- [x] 训练页 `/training` 热力图在深色与浅色主题下人体剪影与肌肉分片清晰、无裁切错位，点击各肌肉区均可正确联动右侧明细；
- [x] 动作详情页 `/exercises/:id`（分别测试胸/背/腿/核心/多协同复合动作）能直观看出主练与协同肌分布；
- [x] `cd web && npm run build` 类型检查与构建 0 报错。
