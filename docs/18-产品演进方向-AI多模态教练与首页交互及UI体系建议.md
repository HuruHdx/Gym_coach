# 18 · 产品演进方向：AI 多模态教练、首页交互与 UI 体系建议

> 日期：2026-11-27  
> 性质：**产品与技术选型参考备忘**（供确认后续方向，非即时施工工单）。  
> 基准：结合当前 `Gym_coach`（H5 + API）与 [`gym-ui/DESIGN.md`](../gym-ui/DESIGN.md) 的实际代码与技术栈梳理。

---

## 1. 先定准产品基调：H5 是主战场，后台只是武器库

- **主价值在哪里**：后台（工坊 / 动作库 / AI Ops）只是帮你**生产并校准内容**；真正决定这个产品值不值得每天打开、AI 有没有赋能价值的，是 **H5 端「问教练 → 看清楚 → 练起来 → 记下来 → 下次更准」** 的手感。
- **使用现场的物理约束**（与 `gym-ui/DESIGN.md` 一致）：
  - 场景 A（家里/通勤）：问计划、聊目标、查动作库、看训练走势；
  - 场景 B（健身房现场）：**单手、手上有汗、组间休息只有几十秒、光线杂乱**。
  - 结论：**在现场，任何让用户多打字、多点两层弹窗、等半天的设计都是减分项；“少输入、一眼看懂、顺手勾完”才是好产品。**

## 2. AI 教练功能演进：多模态回复 + 训练全链路赋能

### 2.1 对话回复的多模态组合（不止于纯文本）

目前 [CoachPage.tsx](../web/src/pages/CoachPage.tsx) 已支持三类卡片：`training_draft`（今日课表）、`exercise_ref`（动作卡）、`plan_recommend`（计划推荐）。下一步最值得补强的多模态交互：

1. **「动图 + 带声教学 + 文字要点」双轨动作卡**（对应 Admin `16` 号方案）：
   - 问「某某动作怎么做 / 注意什么」时，文字简练给 3 条核心要领，下方动作卡优先提供**可手动点播、带人声讲解的 `highlight_video`**，无教学视频时回退静音 `demo` 循环动图；
   - 卡片上可顺手加一个轻量按钮 **「＋ 加入今日训练」**（不用非得跳去详情页再加）。
2. **结构化对比与数据洞察块（轻量富文本 / 迷你组件）**：
   - 目前教练气泡 `m.text` 只是纯文本渲染（无 Markdown 表格或重点块）。
   - 问「高位下拉和划船区别」「我最近卧推涨了吗」「哪里练得少」时，除纯文字外，可支持**轻量对比卡 / 数据小卡**（例如直接内嵌迷你 `Sparkline` 走势 + 1RM 变化芯片 + 「去训练页看热力」或「按今天状态排一场」直达按钮）。
3. **「边练边问」的上下文感知**：
   - 用户正在练今日胸训（`active` 场次），直接切到教练页说「这个器械有人占了」「做到第 3 组右肩有点刺痛」，教练应该**自动知道你当前正在练哪场、做到哪个动作**，直接给出替代方案并支持一键更新当前场次（而不是重新排一整套从头再来）。

### 2.2 训练过程中的 AI 减负（比重型视频姿态纠错更早出价值）

| 能力 | 解决什么痛点 | 为什么比一期上 FormCheck 更值 |
|---|---|---|
| **语音一句话记组（Voice-to-SetLog）** | 健身房汗手/戴助力带时不想反复点 `+ / -` 步进器 | 今日页长按说「卧推 60 公斤 8 个，最后挺力竭」→ 语音转写 + 轻模型抽取 `actual_weight / actual_reps / feeling` 自动填入并打勾，研发成本低、每天都能用上。 |
| **跟练中「一句话整场微调」** | 健身房突然赶时间、没空位器械、精力差 | 基于今日板块或正在练的动作，一键让教练按「20 分钟 / 只用哑铃 / 护肩」就地替换，保留跟练进度。 |
| **练后 AI 复盘 + 下次负荷锚点** | 练完只有冰冷数字，不知道下次该加重还是稳住 | 结合 `feeling`（轻松/合适/力竭）、1RM 涨跌和休息间隔，生成 2～3 句具体复盘，并直接影响下一次排课与模板展开时的默认重量。 |

### 2.3 为「二期营养 & 热量消耗」提前接好的多模态方向

当后续切入营养阶段时，最能发挥多模态 AI 优势的功能是：
1. **拍照识餐（Vision → 热量 / 蛋白质估算）**：用户拍一张食堂/外卖/自制健身餐，AI 估算热量与三大营养素并一键记入当日（比搜千字食物库录入实用 10 倍，用户才会长期记录）。
2. **训练消耗 + 饮食缺口联动**：把现有 `TrainingSession.duration_minutes`、`Exercise.modality`（抗阻/有氧/HIIT METs 系数）与体重曲线 `ProfileHistory` 串起来，教练就能主动说「今天练腿消耗偏高，晚饭多补 30g 碳水和一勺蛋白粉」。

## 3. 首页（今日页 `/`）与核心交互体验优化方向

今日页是用户每天打开次数最多的页面，后续打磨重点建议放在**「单手效率」与「状态反馈」**：

1. **「当前正在做这一组」的极致单手热区**：
   - 训练中（`running`）时，把**「当前动作 + 组号 + 上次成绩 + 完成这一组大按钮」**稳定留在拇指舒适区；
   - 勾选当前组后给轻震动反馈（`navigator.vibrate?.(12)`），该组完成后若整动作完结，顺滑自动展开下一动作。
2. **「隐形组间计时」取代干扰弹窗**：
   - 你们之前果断砍掉强制组间倒计时弹窗非常明智；更好的替代方案是利用 `TrainingSetLog.completed_at`，在刚勾完一组后，顶部或当前动作旁安静显示一个只读小读秒 **`已休 01:18`**，扫一眼就知道有没有聊微信超时，完全不弹窗打断。
3. **支持「今日多练」与「快进快出」**：
   - 练完一场后允许随时开第二练或从动作库顺手加练 2 个动作（见 `17` 号工单），不强迫「每天只能有一条记录」。
4. **顶部进度与休息建议克制化**：
   - 只给真正能指导决策的一句话（例如「背距上次 4 天，今天状态正好」），复杂图表、30 天热力、PR 走势全部留在 `/training` Tab，保持今日页纯粹。

## 4. H5 UI 组件库与动效库选型建议

基于你们现有的 `web/package.json`（**React 18 + Vite + Tailwind CSS + Lucide Icons + `@dnd-kit` + `echarts` + `html-to-image`**）与 [`gym-ui/DESIGN.md`](../gym-ui/DESIGN.md) 的克制原则：

### 4.1 UI 组件库：不要引入重量级组件库
- **不建议引入** `Ant Design Mobile`、`Vant`、`MUI` 等带强默认样式的组件库：
  - 它们体积大，且自带明显的「通用表单/后台风格」，会直接破坏你们 `tokens.css` 的高级暗/浅主题对比度与四档圆角规范。
- **推荐补充极轻量的「无头交互原语（Headless UI）」**（只接行为和无障碍，样式完全用你们自己的 Tailwind + `tokens.css`）：
  1. **`vaul`（强烈推荐，约 5KB）**：专为移动端 H5 打造的底部抽屉组件（Bottom Sheet），支持**手势下拉跟随关闭、回弹阻尼、键盘避让**，用来替换现在手写的 `TodayDraftSheet` / 换动作弹窗 / 换板块弹层，手机质感立刻上一个档次。
  2. **`@radix-ui/react-dialog` 或保持极简 Portal**：用于居中确认/详情弹窗的焦点管理与 ESC/背景锁定。
  3. **列表/卡片拖拽**：继续沿用已安装的 `@dnd-kit`，无需更换。
  4. **图标**：继续沿用已安装的 `lucide-react`（统一 `strokeWidth={1.75}`）。

### 4.2 动效库：克制、跟手、只动 `transform` / `opacity`
`gym-ui/DESIGN.md` 第 4 节有条非常好的硬规则：**只允许动画 `transform` 和 `opacity`**（不动画 `width`/`height`，避免手机掉帧）。在此前提下推荐：

1. **首选推荐：`motion`（原 `framer-motion` 新轻量包，配合 `LazyMotion` + `domAnimation` 约 15–18KB gzip）**
   - **怎么用才像顶级健身工具（参考 Hevy / Strong 手感）而非花哨动画**：
     - **物理弹簧参数（`spring`）**：统一一套克制的物理曲线（如 `stiffness: 420, damping: 32`），让卡片展开、选中切换、底部按钮按压拥有“配重片咔哒落位”的扎实阻尼感；
     - **`AnimatePresence`**：只用在关键状态切换——如「打勾完成最后一组 → 平滑过渡到已完成 Hero」、教练气泡新卡片柔和入场；
     - **数字与进度条**：进度条继续用 `transform: scaleX(...)` 配合 spring 缓动，不用 `width`。
2. **备选极简方案（零新增依赖）**：
   - 如果想包体极致小，也可以不装 `motion`，只统一升级 CSS `transition-transform duration-200 ease-[cubic-bezier(0.22,1,0.36,1)]` + `vaul`（抽屉手势最重要）。
3. **明确不推荐**：
   - 不上重型 `Lottie` 动画（拖慢首屏、像游戏/营销页）；
   - 不加整页路由左右推拉大转场（在健身房快速在「今日 / 教练 / 动作详情」之间切屏时，快比炫更重要）。

### 4.3 图表与人体结构图
- **人体肌肉图**：自建轻量化矢量组件 `<BodyAnatomySvg />`（标准解剖 SVG Path，接 `tokens.css` 颜色变量，支持点击交互与热力分级，见 `17` 号工单），不依赖带固定配色的第三方大图。
- **趋势走势**：小微曲线继续用轻量内联 SVG `Sparkline`，仅在复杂统计页（如未来体重/容量/热量多轴分析）按需加载 `echarts`。

## 5. 建议的演进优先级总览

1. **当下先收口体验**：跑通 `17` 号工单（今日多练 + 推荐卡状态可切 + 解剖人体图）与 Admin `16` 号（带声教学视频 `highlight_video`）。
2. **接着做「现场减负 AI」**：语音一句话记组 + 隐形组间读秒（用现成 `completed_at`）+ 练中遇阻一句换动作 + 教练卡内嵌教学视频与结构化对比块。
3. **交互质感升级**：引入 `vaul`（原生手感抽屉）+ 轻量 `motion` 弹簧反馈（或统一 CSS 物理曲线）+ PWA 轻震动反馈。
4. **二期大版本再开**：营养模块（拍照识餐 + METs 训练消耗联动）与 FormCheck 侧视视频复盘。
