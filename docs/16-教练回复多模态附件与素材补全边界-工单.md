# 16 · 教练回复多模态附件 + 工坊素材补全边界 · 工单

> 日期：2026-11-26
> 范围：Gym_coach（H5 + API）教练问答回复链路；工坊入库边界引用 Admin `docs/12`，不回改后台定稿。
> 现状台账：[`项目地图.md`](./项目地图.md)；示意稿：[`design/26-教练回复卡片-视频附件示意.html`](./design/26-教练回复卡片-视频附件示意.html)。
>
> **一句话口径**：回答为主、卡片为辅；库里有示范视频才在动作卡内联播放，没有就挂文字卡，没命中就纯文字兜底。不新建视频理解 / 检索管线。

---

## 0. 背景与目标

- **痛点**：用户问「某动作怎么做」，纯文字一长段、专业词看不懂，真实体验者没耐心读；如果能附一段该动作的短视频，点开看轨迹更直观。
- **目标**：教练问答命中已有动作时，把库里现成的示范短视频附在对话里，可点开播放；卡片同时保留跳详情的入口。
- **素材从哪来**：复用工坊切片写库沉淀的 demo + 媒体池单动作上传，不新建视频生产管线。

### 本期不做（非目标）

| 想法 | 结论 |
|---|---|
| 姿态轨迹纠错 / FormCheck | 二期独立项目，方案另议，不进本链路 |
| 视频 embedding / 像素语义 RAG | 成本高；教练问答要的是动作语义文本，不是像素语义 |
| 视频内容理解（自动抽要领 / 轨迹） | 本期不做 |
| 切片自动进教练检索索引 | 切片进计划行 ≠ 进知识索引；进 SKU 也只是多封面 / 示范 |

## 2. 回复规则（定稿口径）

### 2.1 回答为主，卡片为辅

- 正文必须先把答案讲完；卡片只是跳转和可视化入口，**不只甩一张卡让用户自己看**。
- 有视频才内联小窗；无视频挂文字动作卡，不强塞图；未命中兜底纯文字，不挂卡片。

### 2.2 三状态

| 状态 | 条件 | 卡片表现 |
|---|---|---|
| **有视频** | 见 §2.3 门控通过，且 SKU 有 published `demo`（其次 `highlight_video`） | 卡片顶部内联小窗（静音循环、封面 poster、「静音循环」标），下方动作名 / 部位 / 详情跳转 |
| **无视频** | 命中动作，但无 demo / highlight，或门控不允许内联 | 静态文字卡（有 start/end 图留缩略图，没有则占位），不内联视频 |
| **兜底** | 库未命中（无候选可挂） | 纯文字回答，不挂动作卡 |

### 2.3 内联视频门控（实现口径）

同时满足才写 `has_video` / `demo_url`：

1. `branch == "kb"`
2. `qa_kind` **不在** `decide` / `recall` / `compare`
3. `hits` 恰好 1 条，且 **无** `near_miss`

其余场景：

| 场景 | 卡片 | 内联视频 |
|---|---|---|
| `ask` 消歧多候选 | ✅ 静态多卡（现状保留） | ❌ |
| `decide` / `recall` | 可挂静态卡 | ❌ |
| `compare` / 多动作 / `focus_exercises` 补卡 | 最多静态卡 | ❌ |
| `search` / 未命中 | 不挂或纯文字 | ❌ |

> 实现：`_allow_inline_video(grounding, intent)`；`ask`/`decide` 调用处显式 `allow_inline_video=False`。

### 2.4 正文体裁选择（按内容选，不写死）

- **做法 / 步骤**：1 / 2 / 3 分点。
- **对比 / 参数**：表格。本期前端无表格渲染库，先按纯文本分点罗列；待对比场景真实出现后，再二选一：轻量 markdown 渲染，或后端返回结构化块。
- **简单结论**：纯文字一段。
- **库外未命中**：走兜底 LLM 自由发挥，不强行套卡片格式。

## 3. 卡片数据契约

### 3.1 后端（`build_exercise_ref_card`）

`item.meta`：

| 字段 | 说明 |
|---|---|
| `exercise_id` | 动作 id |
| `thumb_url` | 静态展示用；优先封面图，避免 MP4 |
| `demo_url` | 首选 published `demo`，门控未过则为空 |
| `highlight_url` | 次选 `highlight_video`，门控未过则为空 |
| `cover_url` | 小窗 poster / 静态图，取 start/end/tip 或主表图 |
| `has_video` | `bool`，是否内联播放 |
| `muscle` | 可选，副标题展示 |

- 取数用 `media_pack_by_ids`（内部 `_published_media_by_exercise`），**不另开 N+1 查询**。
- `cover_url` **不得**盲用可能指向 MP4 的旧 `thumb_url`。

### 3.2 前端（`ExerciseRefCards.tsx`）

- `has_video` 时：顶部 `LoopClip`（lazy、静音循环、poster=`cover_url`）；底栏点详情跳转；视频区 `stopPropagation`。
- 无视频：维持静态卡；`cover_url`/`thumb_url` 若是视频 URL 则显示「无图」占位，不塞进 `<img>`。
- 小窗高度约 150，对齐 26 号示意稿。

## 4. 工坊切片：入计划 vs 入动作库（边界定稿）

### 4.1 三件互相独立的事

1. **绑定**（确定对应哪个动作）：详情 / 卡片选已有 SKU，或查重后新建；只定对应关系。
2. **要领 / 说明**：抽屉里独立选，只入本计划，或写入库。
3. **示范视频**：切片后独立选，只挂计划行，或勾选写入库。

> **绑定 ≠ 自动入库**：绑了库动作，不代表要领和示范自动进库；进不进库，要领和示范各有各的开关。

### 4.2 动作怎么对上

- 写库挂哪个动作，靠行上已绑定的 `exercise_id`，**不靠后端拿动作名再猜一遍**；后端校验 SKU 存在，不存在直接 404。
- 未绑库的行：「写入动作库」按钮禁用，只能入计划。
- **新建路径**：主动点新建 → 先查重（同名 / 别名命中则提示绑已有，确认才绑）→ 未命中才建一条。切片不会静默自动造新 SKU；不存在「动作还没建、先把示范建出来」。

### 4.3 入库落点（不加新字段）

- 主表 `Exercise` 只有 `image_start` / `image_end`，**没有视频列**。
- 视频落 `ExerciseMedia`：
  - 示范：`role="demo"`，`url` 存 MP4，`meta` 记起止时间 / mime；
  - 封面：`role="start"`，并刷新主表 `image_start`（列表缩略图同源）。
- 旧 published demo / start 改为 archived，**不删记录**；一个动作 + 角色一条在架。
- 只入当前计划的示范：落 `plan_exercises.demo_url` / `demo_cover_url`，与库媒体分开存、互不覆盖。
- 示范只写媒体；要领走抽屉独立入库，不连带写。

### 4.4 写库建议规则（产品目标 · 拟改，非现网）

> **现网（Admin 已接）**：计划模式切片默认只挂计划行；「做成示范视频」弹窗可勾「同时写入动作库」（须已绑库，确认后盖写 SKU demo）；已切未入库可在抽屉点「示范同步进库」。以下为更细的产品演进目标。

- SKU 无 demo 且已绑定：切片时可勾选「同时写入动作库」（默认关，需显式勾）。
- SKU 已有 demo：勾选写库时确认框提示会覆盖；暂不进对比抽屉（要领对照另走「写入库」tab）。
- 女版 / 变体 / 口语名切片：默认只跟计划，或走「派生女版」再写库，避免某套女课 / 某教练口癖切片污染总库。

## 5. 素材补全优先级与存储成本

- **只挑高频常练动作补**，不全量；量级几十到一两百个。
- **补全顺序**：先补问答高频命中、但无 demo 的核心动作；再补孤立 / 辅助动作。
- **规格**：静音短循环、低分辨率、短时长（选区上限 30s）；文件名带 token 防浏览器缓存沿用旧路径。
- **存储**：默认本地 `static/`；可选 S3 兼容（Cloudflare R2 / 阿里云 OSS，`STORAGE_BACKEND=s3`）。当前量级小，小服务器可扛；量大再切对象存储。

## 6. 已知断点（动手前需知，本期不一定修）

- **两套读取源（已部分打通）**：详情 / 目录读 DB；教练问答索引以 `opengym_exercises_enriched.json` 为底，**启动/reload 时合并 DB 有效 Exercise（同 id 覆盖）**。仍未做：排课 `exercises_catalog` 全量改读 DB、正式 DB→JSON 导出流水线。
- **问答 passage 未拼** `cues_zh` / `common_mistakes_zh`；要领沉淀后是否进上下文另议。
- **补 demo ≠ 降未命中**：卡片视频只改善展示；「库有但没认出」仍靠别名 / AI Ops（Admin `docs/14`）。
- 本机数据库旧导致「读不到」不算产品缺陷；以上是架构上两套读取源的衔接问题，是否修待定。

## 7. 验收指标

- 问答命中率；未命中里「库有但没认出」占比（AI Ops 闭环，见 Admin `docs/14`）。
- SKU 有 published demo 的覆盖率；计划行有 demo 的覆盖率。
- 卡片视频内联正确性：门控通过且有 demo 的条目正确出小窗；无视频 / 门控未过不出视频位。
- 工坊「写库」点击率与误覆盖回滚次数（§4.4 落地后再盯）。
- **最小实验**：挑 20 个高频动作，绑库 + 要领写库 +（仅无 demo 时）补 demo；跑一轮内测问答，看未命中是否下降。
