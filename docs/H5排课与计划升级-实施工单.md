> 用途：直接发给开发侧 AI 按序落地。完成后把新增表字段与接口同步回 `docs/项目地图.md`，即可归档本工单。

## 0. 为什么要改（问题清单）

1. **三分化动作搭配与「换动作」推荐外行**：
   - 背二头日会出现「侧平板支撑」，换背部动作会弹出「坐姿哑铃早安式」「坐姿哑铃推举」。
   - 根因①：`PlanExercise` 只有 `role`（主项/辅助/孤立），没有单行目标肌群 `target_muscle`，导致「胸肩三头」板块把三个部位混在一个池子里抽。
   - 根因②：`api/app/slot_roles.py` 孤立动作判定漏了夹胸/飞鸟/腿屈伸/腿弯举/提踵，却把 `核心卷曲/稳定` 归入 `isolation`，抢占了上肢/下肢孤立槽。
   - 根因③：`exercises_catalog.py` 检索与替换把次级协同肌群 `roles` 与主练肌群 `muscle` 等权对待，且同分档 `random.shuffle`，导致协同沾边的动作排到前面。
2. **「练这场」缺少周跟练闭环**：
   - 多日分化计划（如三分化）点「练这场」只生成当天单场，系统不记得用户正在跟练哪套计划、本周练到了第几场，次日打开「今日」又回到空白。
3. **H5「今日」页未开练时太空、「训练计划」列表分类晦涩**：
   - 未开练时半屏空卡片只放两个跳转按钮，没有直接展示今日待练或精选计划。
   - `/plans` 筛选用「框架 / 成品」这种后台建表术语，且三排筛选条堆叠占屏。
4. **动图与二期「动作视频分析」技术口径需提前对齐**：
   - 动作示范切片弃用体积大、画质差的 `.gif`，统一采用**静音循环小 MP4**。
   - 动作视频分析（FormCheck）需修正侧视机位物理指标、补齐上传时的负重/组序输入、对齐 `exercise_name` 主键口径。

## 模块一（P0 · 优先落地）：修复计划配课与「换动作」推荐质量

### 1.1 `PlanExercise` 增加单行目标部位 `target_muscle`

- **修改文件**：`api/app/models.py`、`api/app/db.py`、`api/app/services/plan_seed.py`、`api/app/services/admin_plans.py`（若有动作行增改接口）。
- **表变更**：
  - `PlanExercise` 新增 `target_muscle: Optional[str] = Field(default=None, max_length=16)`（取值为 `胸/背/肩/腿/臂/核心`）。
  - `db.py` 启动迁移检查 `plan_exercises` 列，缺失则执行 `ALTER TABLE plan_exercises ADD COLUMN target_muscle VARCHAR(16)`。
- **种子模板回填（`plan_seed.py`）**：
  - `three-split-classic`（热门三分化）明确每行 `target_muscle`，不再整块混抽：
    - **胸肩三头**：① 主项 `胸`（4×6-8）→ ② 主项 `肩`（3×8-10）→ ③ 辅助 `胸`（3×8-12）→ ④ 孤立 `胸`（3×10-15）→ ⑤ 孤立 `臂`（3×10-15，三头方向）。
    - **背二头**：① 主项 `背`（4×6-8）→ ② 主项 `背`（3×8-10）→ ③ 辅助 `背`（3×8-12）→ ④ 孤立 `臂`（3×10-15，二头方向）。
    - **腿臀**：① 主项 `腿`（4×6-8）→ ② 主项 `腿`（3×8-10）→ ③ 辅助 `腿`（3×8-12）→ ④ 孤立 `腿`（3×10-15）。
  - 对已有数据库启动时做一次轻量补丁：若 `three-split-classic` 下动作行 `target_muscle IS NULL`，按 `order_index` 自动补齐上述部位。

### 1.2 修正 `slot_roles.py` 孤立与核心边界

- **修改文件**：`api/app/slot_roles.py`
- **规则修正**：
  - 扩充孤立判定（按 `movement_pattern` 或中文动作名特征）：包含 `夹胸 / 飞鸟 / 腿屈伸 / 腿弯举 / 提踵 / 耸肩 / 反向飞鸟 / 面拉 / 弯举 / 臂屈伸 / 下压 / 平举` 的抗阻动作归入 `isolation`。
  - **隔离核心动作污染**：`movement_pattern == "核心卷曲/稳定"` 或主肌群 `muscle == "核心"`（如平板支撑、侧平板支撑、卷腹、死虫）**仅当目标部位明确包含 `核心` 时才允许进入候选**，严禁因次级肌群含肩/背而混入胸背肩腿日。

### 1.3 主练肌群强优先 + 三头/二头亚区精准区分

- **修改文件**：`api/app/exercises_catalog.py`、`api/app/services/plan_service.py`
- **检索与替换打分调整**：
  1. **换动作接口 `alternatives_rich(muscle=...)`**：
     - 第一梯队：`item["muscle"] == muscle`（主练肌群完全一致），基础分 `+60`；若 `coach_core=True` 再 `+25`。
     - 第二梯队：`muscle != item["muscle"]` 但 `muscle in roles_of(item)`（仅协同发力），基础分 `+0`；**当第一梯队已有 >= 8 个候选时，直接丢弃第二梯队**，彻底杜绝「换背动作刷出早安式、坐姿推举」。
  2. **计划配课 `_retrieve_for_slot`**：
     - 若 `row.target_muscle` 有值，只检索 `muscles=[row.target_muscle]`（且强制主练肌群匹配优先）。
     - **推日 vs 拉日的「臂」细分**：当 `target_muscle == "臂"` 时，若板块含 `胸/肩`（推日），优先匹配 `sub_region` 或名称含 `三头 / 臂屈伸 / 下压 / 窄距`；若板块含 `背`（拉日），优先匹配 `二头 / 弯举 / 锤式`。

### 1.4 验收标准
- 打开「热门三分化」，胸肩三头 / 背二头 / 腿臀三个板块预填动作全部为地道健身房常见动作，无「侧平板支撑」等核心动作乱入，推日孤立必为胸+三头、拉日孤立必为二头。
- 在背日任意动作点「换动作」，列表前排全为引体/下拉/划船类背部主练动作，不出现推举或早安式。

## 模块二（P1）：H5「周跟练机制」+「今日页」与「计划分类」重排

### 2.1 新增「正在跟练计划」与本周进度计算

区分**多日周期计划（跟练模式）**与**单场专项计划（单挑模式）**：

- **数据层（`api/app/models.py` + `db.py`）**：
  - `UserProfile` 新增两列（`db.py` 自动 `ALTER TABLE` 补列）：
    - `active_plan_id: Optional[str] = Field(default=None, max_length=32)`
    - `active_plan_started_at: Optional[NaiveDatetime] = Field(default=None)`
- **后端接口（`api/app/routers/plan.py` & `plan_service.py`）**：
  - `POST /api/plans/{plan_id}/follow`：设为用户当前跟练计划（校验计划存在且已发布）。
  - `DELETE /api/plans/follow`：退出当前跟练。

    - 提取已练过的 `completed_block_ids: list[int]`（以及今天是否正在练某块）。

  - 单板块计划（`blocks.length == 1`，如博主单部位训练课）：不强调周循环，直接「练这场」。

## 模块三：动作示范动图统一采用「静音循环小 MP4」

供后台内容工坊切片导出与 H5 展示共同遵守：

1. **为什么不用 `.gif`**：5 秒动作 `.gif` 往往 4～8MB 且有色彩噪点，一屏 5 个动作耗流卡顿；同画幅 H.264 无声 `.mp4` 仅 **300～600KB**，清晰且硬件解码省电。
2. **后端 FFmpeg 切片标准命令**（后台选好起止秒数 `start` / `duration` 即可一键生成，比转 GIF 少一步调色板计算、速度更快）：
   ```bash
   ffmpeg -ss {start} -t {duration} -i input.mp4 \
     -an \
     -vf "scale='min(540,iw)':-2,fps=24" \
     -c:v libx264 -preset fast -crf 26 -pix_fmt yuv420p \
     -movflags +faststart \
     output_loop.mp4
   ```
   - `-an`：去掉音轨，确保手机端自动静音循环播放不被系统拦截，也不会打断用户耳机里听的歌。
   - `-movflags +faststart`：元数据前置，H5 边下边播秒开。
3. **H5 渲染组件约定**：
   - 封装通用 `<LoopClip src={url} poster={thumbUrl} />`：
   - 若后缀为 `.mp4` / `.webm`，渲染 `<video src={url} poster={thumbUrl} muted loop playsInline autoPlay preload="metadata" />`（列表页可用 `IntersectionObserver` 进入视口再 `play()`，离开视口 `pause()`）。
   - 若存量数据仍是 `.jpg/.png/.gif/.webp`，自动回退 `<img>`，新老素材无缝兼容。

## 模块四（二期预留）：C 端「动作视频分析（FormCheck）」方案修正备忘

基于 `动作视频分析-方案与参考图` 评审结论，二期开工时按以下修正版落地：

1. **H5 入口落位（不破底部 4 Tab）**：
   - 底部导航保持 `今日 / 教练 / 训练 / 我的` 4 个 Tab 不变。
   - 主入口放在 **「训练」页（`TrainingPage.tsx`）顶部快捷入口区**：由现在的 2 宫格（动作库 / 动作进阶）扩为 **3 入口（动作库 / 动作进阶 / 动作分析）**。
   - 顺手入口放在 **练完结算页（`RecapPage.tsx`）**：提示「拍了训练视频？上传测测这组速度衰减」。
   - 「动作分析」列表页去掉右下角悬浮按钮（避免与全局左下角「燃」球双悬浮打架），统一放右上角胶囊按钮 `＋ 上传`。
2. **上传抽屉必补字段**：
   - 选定动作后，增加 **「本组重量 kg」（默认自动带出今日该动作计划重量或 `ExerciseStats.last_weight`）** 与 **「第几组（可选）」**。没有重量无法给出「下次建议 62.5kg」，没有组序无法精准回填打卡行。
3. **侧视机位与物理指标严谨化**：
   - 删掉单目无标定下算不准的绝对速度（如 `0.62 m/s`）及侧视不可能拍到的左右偏移（如 `偏左 4cm`）。
   - 一期只输出无需距离标定即天然准确的相对量与时间量：**有效次数、每下向心/离心秒数、关节角度 ROM 保持率 %、首末次向心速度衰减 %**，以及侧视可见轨迹特征（杠铃前后水平漂移、卧推抬臀、深蹲早安式髋先起）。
4. **首尾出杠/回架过滤**：
   - 信号处理切分 rep 时剔除首尾非周期性起杠/回架位移；结果页支持用户点按某一下标记「忽略误计（起杠/回架）」并实时重算衰减率。
5. **表结构主键对齐**：
   - `FormCheckVideo` 同时存储 `exercise_id: str | None` 与 `exercise_name: str`（规范化中文名），保证与现有 `TrainingSetLog.exercise_name` 和动作趋势页无缝串联。

## 模块五：自定义计划/板块背景图 & 零成本图床（Cloudflare R2）接入

> 完整后台工单见 `gym-admin/docs/08-内容工坊-视频素材与计划拆解工单.md` §5，两边共用同一套存储底座。

### 5.1 为什么不买 OSS、也不用野鸡免费图床
- 免费公共图床（SM.MS 免费版、路过图床等）有防盗链限制、国内易裂图，且**传不了静音小 MP4 视频**。
- **推荐方案：Cloudflare R2（首选）** —— 兼容标准 S3 协议，**每月免费 10GB 存储 + 1000 万次读取 + 0 流量费（免出口带宽费）**，图片与动作小 MP4 通吃；绑定一个自己的二级域名即可国内稳定直连。单机早期也可不配环境变量，默认落本地 `/static/`，零成本起步。

### 5.2 后端统一存储适配器（`api/app/services/storage.py`）
- 新增 `save_public_asset(data: bytes, key: str, content_type: str) -> str`：
  - `STORAGE_BACKEND=local`（默认）：写本机 `static/` 目录，返回 `/static/...`（现有代码零配置可用）。
  - `STORAGE_BACKEND=s3`：用 `boto3` 上传至 Cloudflare R2（或七牛/OSS，同一套 S3 接口，只改 `.env` 的 `S3_ENDPOINT_URL / S3_ACCESS_KEY_ID / S3_SECRET_ACCESS_KEY / S3_BUCKET_NAME / S3_PUBLIC_BASE_URL`），返回 `https://cdn.xxx.com/...`。
- 现有 `admin_catalog.media_url()` 与 H5 `PlanDetailPage` **已经天然兼容 `https://` 开头的外链**，数据库无需迁移历史字段。

### 5.3 自定义背景图前后端改动点
1. **计划主背景图（`PlanTemplate.cover_url`）**：支持给「热门三分化」「五分化」「XX胸部训练」上传自定义横图，或直接在后台输入框粘贴任意 `https://...` 图片外链。
2. **板块专属背景图（`PlanBlock.cover_url`）**：
   - 后端新增 `POST /api/admin/plan-blocks/{block_id}/cover`（横向等比压缩后调 `save_public_asset`），同时 `PUT /api/admin/plan-blocks/{block_id}` 支持直接传外链。
   - H5 `web/src/pages/PlanDetailPage.tsx` 的板块卡片若存在 `block.cover_url`，叠加暗角渐变渲染背景图，视觉质感对齐主封面。
