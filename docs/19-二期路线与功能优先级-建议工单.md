## 3. P1-A · AI 复盘洞察

### 3.1 定位

基于已有训练记录，生成练后 / 周期复盘：进步了哪、疲劳没、下次怎么调。不依赖新模块，数据底子现成。

### 3.2 链路

1. 拉取近期多场 `TrainingSession` + 对应 `TrainingSetLog`；
2. 聚合：1RM 趋势（`ExerciseStats.estimate_1rm / best_estimate_1rm / recent_1rm_samples`）、负荷量、频次、体感分布（`feeling`）、时长；
3. 对照目标与计划，生成复盘结论与下次调整建议；
4. H5 复盘页 / 教练问答展示。

### 3.3 编排要点（复杂练手项）

- 多数据源聚合 + 时序趋势计算；
- 规则计算（1RM、容量、疲劳）与 LLM 表达结合；
- 结论可追溯：点评要能对应到具体场次 / 动作 / 数据，不做空泛夸奖；
- 可作为独立子图挂进现有 `graph.py` 链路，复用 LangSmith trace 观测。

### 3.4 口径边界

- 不给伤病 / 康复诊断；异常体感提示线下咨询专业人士。
- 样本不足（场次太少）时如实说明，不硬出结论。
- 调整建议以加片 / 稳重 / 换动作为主，不替用户做高风险决策。

### 3.5 验收

- 能基于近 N 场记录给出：主要进步点、疲劳/体感判断、1~2 条下次调整建议；
- 每条结论可回溯到记录数据；
- 样本不足 / 缺字段时有兜底话术，不报错。

## 4. P1-B · 热量消耗粗算展示

### 4.1 现状技术债（先还）

- 前端 Onboarding / 资料页已能填**性别、出生日期**，但只写浏览器本机 `localStorage`（`gym-coach-profile-extras`）；后端 `Profile` 表、Create/Update/Out schema、`/api/profile` 接口**均无这两个字段**。
- `profileView.ts` 已留 TODO：性别、出生日期不在接口，先记本机，热量阶段再入库。
- **落地改动**：
  - `Profile` 补 `gender`（男 / 女）、`birth_date`（YYYY-MM-DD，年龄由它算）；
  - schema 三态（Create / Update / Out）带上；
  - PATCH body 提交这两个字段，前端不再只写本机；
  - 老用户本机存过的做一次性回写兜底。

### 4.2 计算口径（备查公式）

**基础代谢 BMR**（Mifflin-St Jeor）：

- 男：`10×体重kg + 6.25×身高cm − 5×年龄 + 5`
- 女：`10×体重kg + 6.25×身高cm − 5×年龄 − 161`

**活动系数 PAL**（按 `days_per_week` 训练频率默认套档，允许手动改）：

| 每周训练 | 系数 | 档位 |
|---|---|---|
| 基本不动 / 久坐 | 1.2 | 久坐 |
| 1~2 次 | 1.375 | 轻度 |
| 3~5 次 | 1.55 | 中度 |
| 6~7 次 | 1.725 | 高强度 |

**TDEE = BMR × PAL**。

**目标热量**：增肌 `TDEE + 200~300 kcal`；减脂 `TDEE − 300~500 kcal`；维持 `TDEE`。蛋白 `1.6~2.2 g/kg`，脂肪 `0.8~1 g/kg`，其余碳水；落现有 `calorie_target / protein_target_g` 字段。

### 4.3 训练消耗粗估

无心率 / 手环数据，训练消耗只能估算，**压低误差但不消除**：

- **MET 法**：`消耗 ≈ MET × 体重kg × 时长h`；MET 按动作类型分档：

  | 动作类型 | MET 区间 |
  |---|---|
  | 下肢 / 复合（深蹲、硬拉、卧推） | 5~6 |
  | 上肢推 / 拉 | 4~5 |
  | 自重 / 核心 | 3~4 |

- **负荷量校准**：`重量 × 次数 × 组数` 作为强度因子，辅助修正 MET 取值。
- **休息不逐组监测**：训练时不会一直看手机，H5 切后台 / 锁屏 JS 可能挂起；组间休息按默认值（如 90 秒）统一扣，或不扣、保守低估。
- **输出区间**，标注「估算」，不给精确个位；日常非训练消耗（NEAT）不混进训练消耗。

### 4.4 展示口径

- 前期主记负荷量、场次、重量次数趋势；热量消耗放次要参考位置。
- 缺档案字段（性别 / 年龄 / 身高 / 体重）先引导补全，不硬算。
- 误差提示：公式为估算，个体代谢差 10~15%，靠 2~4 周体重趋势校准目标。

### 4.5 本期不做

- 食物库、饮食日志、「今天吃了多少、还差多少」摄入闭环；
- 拍照识餐；
- 心率 / 可穿戴接入、后台持续计时、组间倒计时监测。
- 以上等第一期评测收口、必要时再单独立项。

## 5. P2 · 海报 / 笔记卡

### 5.1 两种卡定位

| 卡 | 时机 | 内容 | 数据源 |
|---|---|---|---|
| 练后战绩分享海报 | 练完觉得不错 | 计划动作清单 + 实际重量次数 + 体感 + 突破 | `TrainingSetLog`、`ExerciseStats`、场次记录 |
| 练前计划笔记卡 | 练前查看 | 动作、组次、替代、要领、示范图 | `PlanExerciseRow`、`PlanTemplate/Block.cover_url` |

> 区别于记事本：不做「记录自己做了 XXX」的笔记模块；打勾跟练、每组感受已在现有流程记录，海报从已有记录自动组装，用户不额外录入。

### 5.2 数据字段（现成）

- 计划行：`target_sets / target_reps / warmup_sets / alternatives / note / cues_zh / demo_cover_url`；
- 训练记录：`actual_weight / actual_reps / feeling / note`；
- 突破对比：历史最佳 vs 本场；模板 / 板块封面 `cover_url`。

### 5.3 排版与合成

- 前端固定模板排版：头部 / 标题 / 数据区 / 明细列表 / 封面素材区 / 底部署名；一套骨架按卡类型插拔。
- 截图复用现有 `html-to-image` `toPng`（2 倍像素），存相册；不做社交一键分享，用户手动转发。
- 每块留空态：无封面放纯色块，无 PR 显示「今天没破纪录」，无要领不渲染该行。

### 5.4 文生图边界（重要）

- **文字、动作名、组次、重量、封面图一律走模板 / 真实素材**，不交给生图模型；模型不碰精确中文和数字。
- 生图模型第一版**不接入**；背景先用预制模板（暗色打卡风 / 浅色简约风）。
- 后期若接生图，只出无文字、无人物、留白的背景氛围底图；同风格缓存复用，失败兜底预制图。
- **AI 不生成动作示范人物图**（姿势易畸形、误导训练）；示范图只用入库真实素材。
- 装饰图标继续用现成图标库，不为每张卡生成。

### 5.5 验收

- 两种卡能由真实数据 + 真实封面自动组装，空态不残留空白坑；
- 截图导出清晰（2 倍像素），背景图 / 字体加载完成后再合成，避免截空白；
- 不出现模型生成的错字、串行数字、畸形人物。

## 6. P3 · 视频分析 FormCheck（二期独立项目）

### 6.1 定位

姿态 / 轨迹动作分析，独立于教练回复链路；本期不动代码，方案另议。入口已占位：`/training/form-check` + Recap CTA。

### 6.2 范围收敛

只覆盖四大项 + 少量常见动作：**深蹲、硬拉、卧推、高位下拉**；不全动作库铺开。

### 6.3 链路概要

1. 上传侧视 / 正面视频（第一版不做实时摄像头）；
2. 后端 FFmpeg 抽帧（15~20fps，降分辨率）；
3. 姿态模型出关键点（后端 Python `mediapipe` 起步，不够再换 YOLOv8/11-pose）；
4. 规则判定：关节角度、躯干倾角、轨迹幅度、往复次数、节奏 / 速度衰减；
5. 报告回放叠加骨架 + 角度标注 + 问题点 + 关键帧。

### 6.4 已知局限

- 单目视频缺真实深度，前后方向（夹肘、肩胛后缩）判不准；侧视角判角度最可靠；
- 遮挡丢点需插值 / 丢弃，不硬算角度；
- 规则不能一套通用，逐动作配检查项；第一版挑结构简单、侧视清晰的动作跑通；
- 计数 / 节奏 / 衰减比姿势纠错先落地；不下诊断式结论。

### 6.5 前置条件

- P0 收口完成；记录与统计链路稳定；
- 先录标准 + 问题样片留评测基线；
- 异步长任务状态、失败重试、临时文件清理方案就绪。
